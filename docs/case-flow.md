## 2. 狀態

| 資料裡的值 | 管委會、管理人員看到 | 住戶看到 | 改了什麼 |
|---|---|---|---|
| `pending` | 待受理 | 已收到 | |
| `accepted` | **處理中** | 處理中 | 原本叫「已受理」（2026-10-15 改）。管理端和 `in_progress` 顯示一樣，篩選也合在一起；要看還沒派廠商的，看卡片上的「尚未派廠商」 |
| `in_progress` | **處理中** | 處理中 | 原本叫「施工中」。聯繫廠商、等報價這種事不是施工 |
| `to_verify` | **待結案** | 處理中 | 原本叫「待驗收」。驗收是管理人員在現場做的，這一步是等主委或副主委結案 |
| `closed` | 已結案 | 已完成 | |

資料裡的值不改，只改顯示的文字（`CASE_STATUSES` 的 `label`）。假 API 還是分得出 `accepted`（受理了、還沒派廠商）和 `in_progress`（派了廠商），例如派廠商只能在這兩種狀態做。

## 3. 交辦給管理人員：另開一筆交辦，用 `caseId` 連到案件

`data-model.md` 原本寫「主委或副主委受理後再交辦給管理人員，資料上要怎麼記還沒定」。**定案：另開一筆交辦**（2026-10-15）。

- 現成的確認、退回、撤回（交辦的撤回，不是通報的）、待辦（「交辦給我的」「待我確認」）都能直接用
- 假資料本來就這樣寫：`TASK-092` 連到 `CASE-20260925-003`，張管理員在案件上寫處理紀錄
- 資料裡案件的負責人（`assigneeId`）還是受理的主委或副主委，不會換人
- **畫面上的「負責人」是實際處理這件事的人**（2026-10-15）：交辦出去的就是交辦對象（例如張管理員），沒交辦的就是受理的人。假 API 另外算出來給畫面（`handlerLabel`），資料不改。案件詳情的「負責人」、案件卡片的說明（待結案、已結案沒有廠商的）都顯示這個
  - 交辦被撤回 → 換回受理的人；被退回的還是交辦對象（退回是請對方再做一次，交辦還在進行中）
  - 待結案、結案後 → 顯示按「完工驗收」的那個人（待結案是 2026-10-16 加的）
- 一件案件同時只能有一筆「進行中」的交辦。撤回後可以再交辦（被退回的交辦還在進行中，不能另外再交辦）
- 被交辦的管理人員可以在這件案件上派廠商、寫處理紀錄、完工驗收（權限表本來就是管理人員都能做，這裡不另外限制）

## 4. 每一步的規則

「住戶看到」是處理紀錄的 `residentText`，住戶的通報詳情頁會自動顯示（沒寫就不給住戶看）。

### 4-1 受理 `acceptCase(id, userId, { category, equipmentId })`
- 誰：主委、副主委、管理人員（權限表）
- 什麼時候：待受理
- 做什麼：狀態 → 已受理；資料上的負責人 = 受理的人（畫面上的「負責人」交辦後會換成交辦對象，見第 3 節）
- **畫面上按了就受理**（2026-10-15），上面跳提示「已受理」，不開彈窗。所以下面兩樣現在受理時不填：問題分類在案件詳情的「問題分類」卡片改（4-1-0，2026-10-17）；關聯設備在「關聯設備」卡片選（4-1-1）。假 API 還是可以傳
  - 問題分類（選填）：住戶通報時先歸「其他」，這時改成正確的
  - 關聯設備（選填）：有選的話，設備狀態跟著變，結案時進維修歷史
- 紀錄：「已受理」／「李主委受理」
- **處理期限受理時不填**（2026-10-18 和 013 定，見 4-1-2）

### 4-1-0 問題分類 `updateCase(id, userId, { category })`（2026-10-17 加）
- 誰：主委、副主委、管理人員
- 什麼時候：已受理、處理中（和選設備、派廠商一樣；待結案就不能改了）
- 畫面：案件詳情的「問題分類」卡片，下拉選單（7 種，見 `ISSUE_CATEGORIES`），一定有值（住戶通報時是「其他」）；和其他卡片一樣按底部「更新進度」才存
- 紀錄：併進「更新進度」那一筆，例如「問題分類：漏水」；選回原本的不寫
- 住戶看到：不寫（是管理端內部的資料）

### 4-1-2 處理期限（2026-10-18 和 013 定，PR #122 討論）
- **案件不自己填期限**：期限通常是交辦出去才需要，新增交辦頁已經有「完成期限」，案件再填一次會變成兩個日期
- 案件的「處理期限」= 交辦的完成期限（假 API 的 `caseDeadlineOf`，`getCaseById` 回傳的 `deadline`）：
  - 有還沒完成的交辦（進行中、待確認）→ 那筆交辦的期限
  - 沒有的話 → 最後一筆已完成的交辦的期限（已結案的也看得到當初的期限）
  - 沒有交辦、交辦被撤回、交辦沒填期限 → 「尚未設定」，**不算逾期**
- 逾期：有處理期限、還沒結案、期限那天已經過了。案件的逾期徽章、案件詳情的「已逾期 N 天」、待辦的到期日都看這個
- 缺點（013 同意）：管理人員自己受理、自己處理的案件不會逾期（那種期限本來就是他自己訂的）
- 名稱：2026-10-17 前文件叫「完成日期」，畫面一直叫「處理期限」，統一成處理期限。是「要在哪天前處理完」，不是實際完成的日期，實際的看 `completion.at`、`closedAt`

### 4-1-1 關聯設備 `setCaseEquipment(id, userId, equipmentId)`（2026-10-15 加）
- 誰：主委、副主委、管理人員
- 什麼時候：已受理、處理中（可以換）
- 畫面：案件詳情的「關聯設備」卡片是一個 Combobox（`ui/combobox`，2026-10-15 改，拿掉灰色區塊和「選擇設備 ›」）：框本身就是輸入框，點了往下展開設備清冊，在框裡打字就篩選；選好後再點，框上的字會整段選起來，直接打字就是重新搜尋。選一台就先記下來，按底部「更新進度」才存
- 「廠商履歷」卡片拿掉灰底區塊（2026-10-15），欄位直接帶入存好的廠商和預約時間；不能改的人只看文字
- 案件詳情的「施工日誌」卡片拿掉（2026-10-15，013 提的：主要流程用不到，處理紀錄已經能記）；廠商的預約到場時間改用 `DatePicker`、`TimePicker`
- 設備狀態：一律先變待維修，廠商第一次到場那天起才算維修中（照 4-3、#69 的規則，用日期算）；換掉的那台變回正常使用中
- 紀錄：「關聯設備」／「張管理員關聯設備『電梯（A 棟）』」（不給住戶看）
- 結案時，這台設備的維修紀錄多一筆（4-7）

### 4-2 交辦 `createTask(userId, { title, content, assigneeId, deadline, caseId })`
- 誰：主委、副主委（權限表）
- 做什麼：新增一筆進行中的交辦；有 `caseId` 的話，案件多一筆紀錄
- 紀錄：「交辦」／「李主委交辦給張管理員（TASK-105）」
- 住戶看到：不寫（住戶不需要知道內部分工）
- 被交辦的人：待辦裡出現在「交辦給我的」（現成的）
- 這個函式也給「會議決議交辦」用（那時 `caseId` 不傳）

### 4-3 派廠商 `assignVendor(id, userId, { vendorId, vendorName, scheduledAt })`
- 名冊裡的廠商傳 `vendorId`；名冊裡沒有的可以自己打名字，傳 `vendorName`，先只記在案件上（之後再自動加進廠商名冊）
- 誰：主委、副主委、管理人員
- 什麼時候：已受理、處理中（可以換廠商）
- 做什麼：記下廠商；狀態 → 處理中
  - **預約到場時間**（`scheduledAt`，選填）：廠商敲定哪天來就填，例如 10/3 14:00
- 紀錄：「派廠商」／「張管理員指派 大同電梯，預約 10/3 14:00 到場」
- 住戶看到：「已安排廠商，預計 10/3 到場。」（沒填預約時間就是「已安排廠商處理。」；不寫廠商名稱）
- 設備：還是待維修。**廠商到場那天才變維修中**（2026-10-15 改，原本派廠商就變）：假 API 記下廠商第一次到場的時間（`firstVisitAt`），用日期算。沒填預約時間的，一直是待維修

### 4-4 處理紀錄 `addCaseLog(id, userId, { text, residentText, scheduledAt })`
- 誰：主委、副主委、管理人員
- 什麼時候：還沒結案
- 紀錄：「處理紀錄」／`text`（管理端看的，可以寫廠商、報價這些細節）
- **住戶看到：另外寫一句 `residentText`**（選填，沒寫就不給住戶看）。管理端的寫法可能有廠商名稱、報價，所以不直接給住戶看
- 畫面（2026-10-18 013 調）：「給住戶看的說明」在上、「處理內容」在下；打住戶說明時處理內容同步出現一樣的字，不用打兩次；自己動過處理內容（例如補一句給主委看的）就不再同步，刪光會恢復同步
- 改期時，如果廠商已經來過（第一次到場的時間已經過了），設備維持維修中；還沒來過就跟著新的日期改
- **改期**：施工比預計久、要改天再來時，在案件詳情「廠商履歷」卡片改預約到場時間，處理內容寫原因，按一次「更新進度」一起存（2026-10-15 改：處理紀錄的表單拿掉「改期」欄位）。例如管理端「大同電梯更換零件需調貨」，住戶看到「廠商將於 10/5 再次到場處理。」

- 「處理進度與留痕」的紀錄有備註（`note`，例如住戶修改通報時改完的內容）時，管委會、管理人員端也在說明下面用 `type-note` 灰色小字顯示，和住戶端的處理進度一樣（2026-10-15）

### 4-4-1 更新進度 `updateCase(id, userId, { equipmentId, vendor, log })`（2026-10-15 加）
- 按鈕原本叫「更新現況」，2026-10-15 改名「更新進度」
- 案件詳情的關聯設備（Combobox，框裡打字就能搜尋）、廠商、處理紀錄三張卡片，欄位直接顯示、邊填邊記下來（沒有「取消」「確定」），按底部「更新進度」一次存
- 底部按鈕：動作（完工驗收、結案）在左、「更新進度」在右；右邊是主要的藍色
- **只寫一筆紀錄**：「更新進度」，內容一項一行、言簡意賅，**不寫是誰按的**（受理、交辦之後就知道是誰在處理；紀錄的 `actorId` 還是有記）。原本會拆成關聯設備、派廠商、處理紀錄三筆。例如：

  ```
  給住戶：廠商將於 10/21 到場處理。
  ```
  最後一行「給住戶：…」是處理紀錄裡「給住戶看的說明」，有寫才有，管理端才看得到這次給住戶看了什麼
- 住戶看到：派廠商、處理紀錄給住戶看的那幾句接在一起；都沒有就不給住戶看
- 待結案的案件只能寫處理紀錄；有一樣做不了就全部不做
- 單獨的 `setCaseEquipment`、`assignVendor`、`addCaseLog` 還在（各寫一筆），畫面現在都用 `updateCase`

### 4-5 完工驗收 `completeCase(id, userId, { note, photos, cost })`
- 誰：主委、副主委、管理人員
- 什麼時候：已受理、處理中（已受理也可以：管理人員自己就修好的，例如換燈管，不一定要派廠商）
- 為什麼完工和驗收是同一步：廠商來處理時當場驗收，沒驗收完不能走，所以**沒有「驗收不通過」**
- 做什麼：記下完工紀錄（`completion`：時間、備註、照片）
  - **管理人員按的** → 狀態 → **待結案**，回到主委、副主委審核（2026-10-15 改：管理人員自己受理的也一樣，原本是直接結案）。有交辦給這個人、進行中的交辦**一起回報完成**（回報備註就用完工備註），不用再到交辦頁按一次
  - **主委或副主委按的**（自己處理的）→ **直接結案**，接著做 4-7。回報完成頁會多一欄維修費用（`cost`，有關聯設備才有，和 4-6 的結案頁一樣；2026-10-16 補，原本直接結案沒地方填費用，維修紀錄就沒有費用）。不另外放結案說明：備註說明就是說明，兩個文字框合成一個（2026-10-16 suzy 決定）
- 紀錄：「完工驗收」／完工備註
- 住戶看到：「維修已完成，等待管委會結案。」（主委、副主委直接結案的就只顯示 4-6 的那一句）
- 待辦：**主委、副主委兩個人的待辦都出現**「**待我結案**」（2026-10-15 改：原本只有負責人），說明「張管理員已完工驗收，請結案」，誰先結案都可以。
- 通知（2026-10-16）：管理人員按的，主委、副主委都收到「案件待結案」（點了到案件詳情）。還沒看過的「待我結案」排在待辦最前面，首頁看得到；打開那件案件詳情就算看過
- 連到這件案件的交辦不會另外出現「待我確認」（結案時會一起確認完成）

### 4-6 結案 `closeCase(id, userId, { cost, note })`
- 誰：**主委、副主委**（2026-10-15 改：原本只有負責人；管理人員不能結案，權限表也改了）。不管是誰受理、有沒有交辦，兩位都可以結案
- 什麼時候：待結案（主委或副主委自己按完工驗收的，在 4-5 就一起結案了）
- 做什麼：狀態 → 已結案、記下結案時間；有連到的交辦（待確認）一起確認完成
- 維修費用（選填）：只有委員填得了，管理人員沒有這一欄（管理人員看不到費用，權限表 2026-10-14）。費用記在設備的維修紀錄上，所以沒有關聯設備的案件不記費用
- 結案說明（選填）：寫在「已結案」那筆紀錄的第二行，管理端看得到，住戶看不到
- 廠商評分：2026-10-16 拿掉了，結案不評分（舊的假資料還有評分，廠商詳情的平均評分照樣算）
- 紀錄：「已結案」／「李主委結案」，有結案說明的話下一行是說明
- 住戶看到：「已完成維修，感謝你的通報。」
- 設備：→ 正常使用中

### 4-6b 退回 `returnCase(id, userId, reason)`（2026-10-16）
- 誰：主委、副主委（和結案同一批人）
- 什麼時候：待結案。結案頁底部是「退回」「確認結案」兩顆按鈕，按「退回」跳彈窗寫退回原因（必填）
- 做什麼：狀態 → 處理中，請完工驗收的人再處理一次。和 4-5 的「沒有驗收不通過」不衝突：那是廠商當場驗收，這是主委、副主委審核管理人員的回報
  - 有連到這件案件、待確認的交辦 → 一起退回（回到進行中、記下退回原因），通知交辦對象「交辦被退回」
  - 沒有交辦的（管理人員自己受理的）→ 通知按完工驗收的人「案件被退回」
- 完工紀錄（`completion`）清掉，處理紀錄裡的「完工驗收」那一筆留著
- 紀錄：「退回」／「李主委退回：原因」
- 住戶看到：「管委會確認後還需要再處理，處理中。」
- 之後：管理人員處理完再按一次完工驗收，又回到待結案

### 4-7 變成維修歷史（結案時自動做）
- 案件有關聯設備的話，那台設備的紀錄多一筆：日期＝結案日、類型＝維修、內容＝案件標題、廠商、費用、`caseId`
- 沒有關聯設備的案件（例如住戶噪音）不進維修歷史，案件本身就是紀錄

### 4-8 結案後又發現問題
- 驗收通過後過幾天又壞了：**再開一件新的**（住戶再通報一次，或管理端登記），不把舊案件重新打開。舊案件的結案時間和維修紀錄已經寫好了，重新打開會亂掉
- 新案件可以連到上一件（之後再加欄位，示範先不做）
