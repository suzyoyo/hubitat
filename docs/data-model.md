# 好彼社區｜資料模型（假資料規劃）

從 Figma wireframe 三端（住戶、管委會、管理人員）的畫面反推而來。
狀態：**已確認（2026-10-06）**，依此分三批建立 `src/mocks/` 的假資料。

## 核心觀念：三端看的是同一批資料

同一筆資料，三端看到的內容和能做的事不同。例如：

```
住戶送出「通報」 ──→ 變成一筆「案件」 ──→ 管理人員受理、派廠商、標記完工
                                     └──→ 管委會追蹤、交辦、結案
                                     └──→ 住戶在「我的通報」看到進度
```

所以資料只建一份，由假 API 依角色決定回傳哪些欄位。

## 資料總覽

| # | 資料 | 檔案 | 說明 | 哪一端會用 |
|---|---|---|---|---|
| 1 | 社區 | `community.js` | 社區基本資料、地點清單、問題分類、內部聯絡、鑰匙清單 | 三端 |
| 2 | 成員 | `users.js` | 住戶、委員、管理人員；屆次與任期 | 三端 |
| 3 | 案件 | `cases.js` | 通報、報修（取代目前的 `reports.js`） | 三端 |
| 4 | 交辦 | `tasks.js` | 管委會指派給管理人員的工作 | 管委會、管理人員 |
| 5 | 提案 | `proposals.js` | 提案與委員簽核 | 管委會 |
| 6 | 公告 | `announcements.js` | 社區公告（含審核流程） | 三端 |
| 7 | 會議 | `meetings.js` | 會議紀錄、決議事項、住戶留言 | 三端 |
| 8 | 廠商 | `vendors.js` | 廠商名冊、聯絡窗口 | 管委會、管理人員 |
| 9 | 合約 | `contracts.js` | 廠商合約（含歷次合約） | 管委會、管理人員 |
| 10 | 設備 | `equipment.js` | 設備清冊、保養與維修紀錄 | 三端 |
| 11 | 文件 | `documents.js` | 法定文件、公開文件、規約 | 三端 |
| 12 | 時間軸 | `timeline.js` | 社區大事記 | 住戶、管委會 |
| 13 | 通知 | `notifications.js` | 各角色的通知 | 三端 |
| 14 | 留存 | `quickSaves.js` | 拍照快速留存（收據、單據、現場照片），之後再補齊資料 | 管委會、管理人員 |

**不另外存、由假 API 計算出來的：**
- **我的待辦**：從交辦、案件、提案、快到期的合約與文件、待補資料中彙整
- **決議事項**：從各場會議的決議彙整
- **交接包**：從未結案案件、未執行決議、會議、合約、廠商彙整（另存一段「卸任者的話」）
- **緊急標示使用紀錄**：從標示為緊急的公告彙整
- **搜尋結果**：從案件、會議、文件、合約中搜尋

## 資料之間的關係

```
社區 ─┬─ 地點（棟別 → 地點）
      └─ 成員 ─┬─ 住戶
               ├─ 委員（主委、副主委、財務、修繕、監察）
               └─ 管理人員（總幹事、警衛）

案件 ──→ 通報人（成員）、地點、負責人（成員）、廠商、設備
  ├─ 附議（其他住戶「我也遇到了」）
  ├─ 處理進度紀錄
  └─ 施工日誌、廠商評分

交辦 ──→ 交辦人、交辦對象、關聯案件 或 關聯決議
提案 ──→ 發起人、選項（廠商報價）、各委員的簽核
公告 ──→ 發布者、審核者、影響地點、關聯案件、關聯設備
會議 ─┬─ 決議 ──→ 負責人、（交辦）
      └─ 住戶留言 ──→ 留言人、管委會回覆
廠商 ─┬─ 聯絡窗口
      ├─ 合約（多份，有歷次紀錄）
      └─ 負責的設備
設備 ──→ 地點、廠商；保養與維修紀錄 ──→ 關聯案件
```

## 各資料的主要欄位

### 1. 社區 `community.js`
- 基本資料：名稱（好彼社區 翠峰閣）、地址、棟數、戶數、電話
- **地點清單**：範圍（A 棟、B 棟、C 棟、地下停車場、游泳池、中庭與戶外）→ 各範圍底下的地點（電梯、梯廳、樓梯間…）；可停用
- **問題分類**：漏水、設備故障、照明、噪音、水電、門窗鎖具…
- 內部聯絡（中控室、管理室、總幹事、主委）、鑰匙清單

### 2. 成員 `users.js`
- 姓名、棟別、戶號
- 身分：住戶／委員／管理人員。**一個人可以同時是住戶和委員**（畫面有「切換至管委會」）
- 委員職稱：主委、副主委、財務委員、修繕委員、監察委員
- 管理人員職稱：總幹事、警衛
- 屆次與任期（第 12 屆，2026/07～2027/06）

### 3. 案件 `cases.js`
- 案件編號（`CASE-20260925-003`）、標題、地點、分類
- 來源：住戶通報／管理人員代為登記／巡查
- **公開或保密**：公共設施問題公開、涉及住戶行為保密
- 通報人、通報時間、問題描述、照片
- 狀態（見下方「狀態對照」）、處理期限、是否緊急
- 負責人、指派廠商、關聯設備
- 附議的住戶
- 處理進度紀錄（時間、誰、做了什麼）
- 施工日誌、完工備註與照片、廠商評分

**狀態對照**（同一筆案件，三端顯示的文字不同）

| 資料裡的值 | 管委會、管理人員看到 | 住戶看到 |
|---|---|---|
| `pending` | 待受理 | 已收到 |
| `accepted` | 已受理 | 處理中 |
| `in_progress` | 施工中 | 處理中 |
| `to_verify` | 待驗收（待標記完成） | 處理中 |
| `closed` | 已結案 | 已完成 |
| `cancelled` | 已取消 | （已撤回） |

### 4. 交辦 `tasks.js`
- 編號（`TASK-104`）、標題、內容、交辦人、交辦對象、完成期限
- 狀態：進行中／待確認（對方已回報完成）／已完成／已撤回；「已逾期」由期限計算
- 關聯案件或關聯決議（選填）
- 回報完成：附件、備註、回報時間

### 5. 提案 `proposals.js`
- 案號（`2026-088`）、標題、說明、發起人、簽核截止日
- 選項（廠商名稱、報價、附件）
- 各委員的簽核：同意／不同意（或選哪個選項）、意見、日期
- 狀態：簽核中／已通過／已否決

### 6. 公告 `announcements.js`
- 類型：施工／維護／活動／其他
- 標題、內容、日期時間（單日或多日）、影響範圍（可多選地點）或活動地點、主辦單位
- 是否緊急、推播對象
- 狀態：待補／待審核／已發布／已退回／已撤回
- 發布者、審核者、退回原因
- 關聯案件、關聯設備（僅管委會可見）

### 7. 會議 `meetings.js`
- 類型：管委會例會／臨時會議／區分所有權人會議
- 名稱、日期、地點、出席狀況
- 狀態：待整理／待發布／已發布
- 檔案：會議紀錄、簽名簿與委託書（僅管委會可見）
- **決議**：標題、結果（通過 5 票／下次續審／報告事項）、負責人、執行狀態（未執行／進行中／已完成）
- **住戶版內容**：重點摘要、議案列表、全文記錄（已遮蔽個資）
- **住戶留言**：留言人、內容、時間、管委會回覆。管委會首頁的「住戶意見」就是彙整這些留言

### 8. 廠商 `vendors.js`
- 名稱、統一編號、分類（電梯、消防、水電、清潔、保全、園藝）、處理項目
- 合作狀態：合作中／候選／停用
- 聯絡窗口（姓名、職稱、電話、LINE、是否列入緊急聯絡）
- 服務紀錄與統計由案件、設備紀錄計算

### 9. 合約 `contracts.js`
- 廠商、合約期間、金額、服務內容、承諾頻率、檔案、上傳者
- 狀態（合約內／即將到期／已到期／尚未生效）由日期計算
- 金額與合約全文**只有管委會看得到**

### 10. 設備 `equipment.js`
- 名稱、類別、地點、負責廠商、規格說明
- 安裝日期、保固到期日、保養週期、上次保養日（下次保養日由週期計算）
- 狀態：正常／待維修／維修中／已報廢；「保養逾期」「保養將到期」由日期計算
- **保養與維修紀錄**：日期、類型（例行保養／維修）、內容、廠商、費用（僅管委會可見）、關聯案件、照片

### 11. 文件 `documents.js`
- 法定文件：類型、名稱、到期日、是否公開給住戶
- 公開文件：財務報告、安全證明、會議通知
- 規約：版本、修訂日期、修訂說明、章節與條文

### 12. 時間軸 `timeline.js`
- 日期、類型（決議／工程／合約）、標題、說明

### 13. 通知 `notifications.js`
- 收件角色、標題、內容、時間、是否已讀、點了要去哪裡

### 14. 留存 `quickSaves.js`
- 管委會和管理人員都可以使用
- 留存者（成員）、照片、名稱、備註、留存時間、是否已補齊、補齊後歸到哪個案件或設備

## 需要統一的地方（wireframe 內不一致）

wireframe 是分頁畫的，有些內容前後對不起來。假資料只能有一個版本，以下是建議的統一方式：

| 項目 | wireframe 的狀況 | 建議 |
|---|---|---|
| 「今天」的日期 | 住戶首頁約 9/29、管委會約 10/1～10/2、管理人員 10/5 | 統一為 **2026/10/01**。「7 天後到期」「逾期 4 天」這類文字改由日期自動計算 |
| 住戶是誰 | 首頁「8樓之1 李伯伯」，「我的」頁是「陳大明・B 棟 8 樓之 2」 | 用「A 棟 8樓之1 李伯伯」，他同時是修繕委員（管委會端顯示「李委員」） |
| 委員 | 首頁「李委員」，「我的」頁是「王委員・主委」 | 建一組完整的委員名單：王主委、張副主委、陳財務、李修繕、林監察 |
| 管理人員 | 首頁「張管理員」，其他頁是「王小姐・總幹事」「王警衛」「黃組長・警衛」 | 建三位：王小姐（總幹事）、張管理員、黃組長（警衛） |
| 電梯廠商 | 大同電梯、永安電梯、三菱電梯都出現過 | 統一為「大同電梯」 |
| 棟別 | 社區設定是 A、B、C 三棟，但管理人員案件列表有「D 棟」 | 統一為三棟，D 棟那筆改成 C 棟 |
| 第 3 次管委會 | 決議數有 4 條和 2 條兩種寫法；9/20 的星期有「日」和「六」 | 4 條決議；星期由日期自動計算 |
| 設備數量 | 住戶端「共 32 項」，管委會端「共 17 項」 | 假資料建約 12 項，數量由實際筆數顯示 |
| 用詞 | 住戶端「通報」，通知裡出現「報修」 | 假資料不受影響；做畫面時再統一用詞 |

## 已確認的決定

1. **示範住戶**：A 棟 8樓之1 李伯伯。他同時是管委會的修繕委員，所以可以在住戶與管委會兩種身分之間切換。
2. **「通報」和「案件」是同一份資料**（`cases.js`）。住戶送出的通報，就是管委會和管理人員看到的案件。
3. **管委會首頁的「住戶意見」**：住戶看了會議紀錄後提出的疑問。資料放在會議的「住戶留言」裡，管委會首頁把所有會議的留言彙整顯示，可以直接回覆。
4. **「今天」統一為 2026/10/01**（`MOCK_TODAY`）。
5. **快速留存**：管委會和管理人員都可以使用。
