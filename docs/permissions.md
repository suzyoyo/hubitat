# 好彼社區 Hubitat — 角色權限（RBAC）

「誰能做什麼」的正本。畫面要不要顯示某個按鈕、假 API 要不要接受某個動作，都照這份。

整理自 013 的《管委會端規格：角色權限與狀態顏色》（2026-10-11），再對齊之後定案的規則（2026-10-14）。

相關文件：

- 狀態顏色：[dev-guide.md 第 5 節](dev-guide.md#5-樣式規則)
- 各資料的規則細節（審核、交辦、受理）：[data-model.md](data-model.md)

## 1. 原則

**權限有兩層，兩層都要做：**

| | 做什麼 | 我們專案裡是誰 |
|---|---|---|
| 把關（後端） | 有人要做某個動作時，檢查他可不可以，不行就拒絕 | 假 API（`src/mocks/api/`）。之後換成真的後端，這一層搬到伺服器 |
| 體驗（前端） | 沒權限的按鈕、選項、區塊不顯示，不要讓人點了才被拒絕 | 頁面、`roles.js` |

> **為什麼兩層都要**：只做前端的話，懂技術的人可以繞過畫面直接呼叫 API，等於沒有把關。只做後端的話，使用者會一直點到「你沒有權限」，很挫折。

**其他原則：**

- 權限看**角色**，不看職稱。修繕委員、財務委員的職稱只用來顯示（財務委員有兩項例外，見表）。
- **本人**＝只能處理自己發的、或交辦給自己的。
- 沒權限的東西**直接不顯示**，不要顯示成灰色不能按（長輩會以為壞掉）。

**公告的審核**（2026-10-14 定案，細節在 data-model 公告那一節）：主委、副主委發的直接發布；管理人員發的要主委或副主委其中一位審核；標示為緊急的直接發布並通知管委會（《管委會端規格》寫的「主委、副主委互審」「緊急事後審核」不採用）。管理人員修改已發布的公告，通知主委和副主委。已撤回的公告不能修改、不能重新發布，要再發就發一則新的。

**管理人員看會議**（2026-10-14 定案）：和住戶一樣，只看得到已發布的住戶版，看不到內部資料和表決票數（決議只顯示「通過」）。

**管理人員看合約**（2026-10-14 定案）：看得到服務內容、期間、承諾頻率，看不到金額、不能下載合約檔案（檔案裡有金額，不另外做遮蔽版）。維修費用也看不到。管委會要一起檢討廠商、決定續約，所以委員都看得到金額。

**副主委**：隨時都能做主委能做的事（成員管理、換屆交接），不用先開「代理」。唯一的例外是「發布住戶版會議摘要」只有主委。

## 4. 住戶端的權限

| 功能 | 規則 |
|---|---|
| 新增通報、按「我也遇到了」 | 所有住戶 |
| 修改通報（補充說明、照片） | 本人，而且還沒結案。沒有撤回（2026-10-15 拿掉） |
| 看被代登記的通報 | 同一戶（棟別＋戶號）的住戶都看得到，只能看 |
| 看保密的通報 | 只有通報的人（或被代登記的那一戶） |
| 看別人的公開通報 | 所有住戶，在新增通報「確認是否重複」時看得到同一個地點、還沒結案的 |
| 看會議紀錄 | 只看得到已發布的住戶版；留言只看得到自己的 |
| 會議紀錄留言給管委會 | 所有住戶 |
| 下載會議紀錄 | 拿到的是遮蔽過個資的版本 |
| 加入管委會（輸入邀請碼） | 不是委員的住戶 |
| 切換至管委會 | 只有委員 |
| 住戶看不到的資訊 | 合約金額、維修費用、表決票數、處理人姓名、逾期天數、附議人數（假 API 依 `role` 拿掉，或畫面不顯示） |

## 6. 之後的做法（還沒做）

1. 把權限集中成一個函式，例如 `can(user, 'announcement.publish')`，假 API 和頁面都查它，不要各自寫判斷。現在散在 `roles.js` 的 `canUseMenuItem`、公告假 API 的 `canManage`、`canPublishAnnouncement`、`users.js` 的 `canReviewAnnouncement`，還有頁面裡直接比對職稱的地方。
2. 管委會端加「切換示範身分」（照住戶端在 `/playground` 的做法），才測得出修繕委員、管理人員看到什麼。
3. 把散在各處的判斷換成 `can()`。
